# Spraybot 工件接口实现与审查流程

本文件是项目内 Agent 的流程依据，适用于新增接口，也适用于修改已有接口的生成、参数化、轨迹或审查证据。具体做哪个接口、做到哪一阶段，由当次用户任务决定。项目术语以根目录 [CONTEXT.md](../../CONTEXT.md) 为准；本文件不维护任务排期或静态待办数量。

## 项目职能和边界

本仓库是 Infinigen 的 Spraybot 工件生成 fork。它公开 `spraybot:` 与 `workpiece:` 工件接口，按接口 ID 和 seed 生成完整模型，保留逐面语义与目标面字段，并从生成过程导出参数化描述或结构先验。本仓库还保存新接口的专属喷涂轨迹程序、配对模型的 PaintDS/Web 轨迹，以及机器检查和人工审查记录。Spraybot 仓库负责后续训练格式转换和模型；两仓库通过导出数据交接，不相互导入运行时代码。详见 [兼容契约](compatibility-contract.md)和 [ADR 0007](../adr/0007-colocate-interface-trajectory-programs.md)。

生成接口的职责是提供同类多 seed 的稳定结构与可观察变体，不是把任意 Infinigen Object 函数计为新工件类别。`spray_target` 表示本次喷涂任务的目标面；`geometry_accessible` 仅描述外部自由空间的点连通，不决定涂装意图，也不证明喷枪或机器人可达。`max_passable_radius_m` 的现有估计在多类工件上不可靠，已停用：不得将其用于轨迹规划、机器门禁、人工验收或下游交付。旧样本中如仍有该字段，只视为历史数据。参数化描述、生成接口审查、轨迹审查分别给出结论。

| 结论 | 权威依据 | 证明范围 |
| --- | --- | --- |
| 参数化描述 `ready` | `scripts/spraybot_parametric_readiness.json` 与独立校验结果 | 目标面有可求点、外法向及最终网格面映射，并通过当前多 seed 门禁 |
| 生成接口 `ready` | 已提交的 `reviews/interfaces/<group>__<name>.json` | 被审查的生成行为、逐面字段及导出契约 |
| 轨迹 `accepted` | 已提交的 `reviews/trajectories/<group>__<name>.json` 及当前模型/轨迹哈希 | 该批配对证据经机器几何检查与人工轨迹审查接受 |

这些状态互不替代。轨迹接受仍不等于实体喷枪、机器人运动、膜厚或涂层质量通过。

## 从哪里开始使用

1. 用接口 ID 确认注册入口、结构判据和源生成器。旧入口为 `infinigen2.objects.spraybot.generate_workpiece`，扩展入口为 `infinigen2.workpieces.generate`。先读该接口的代码、[兼容契约](compatibility-contract.md)、相关 ADR 与已有经验记录。
2. 查询已提交的 `reviews/interfaces/` 和 `reviews/trajectories/` 记录、参数化就绪清单，以及相应 Git 提交。review root 是可替换的样本工作区；Git 中的审查文件才是正式结论。旧截图、覆盖统计或未提交的 Web 表单状态都不能代替当前证据。
3. 需要现场生成或复查时，按 [Web 生成器说明](generator-ui.md) 启动或加载 review root；同页切换模型、逐面字段、参数化叠层与配对轨迹。每个 seed 的 `model.json`、OBJ、面字段、参数化数据和轨迹须指向同一次导出。已有配对样本优先直接加载，不为了看页面重新生成。

## 一个接口的完整链路

### 1. 定义工件与生成模型

明确类别的固定结构、允许的种子变化、材料、真实喷涂任务和部件语义。实现生成器时保留部件来源，导出完整网格及 `spray_part`、`spray_target`、`spray_target_reason`；原生实例 ID 单列为 `part_id`。目标面策略与几何通达字段分别定义。保存生成时已有的构造参数与结构先验，避免让下游从最终网格反推。完成标准：多 seed 能生成、保持类别结构、有可观察变化，面字段与导出网格逐面对应。

### 2. 导出和独立校验参数化描述

在构造时捕获源曲面参数、部件归属、求点/法向规则、近似界及最终面映射。使用最终 OBJ 坐标系，明确米/毫米转换；缺失或不支持的描述写 `candidate` 或 `incomplete`。用不导入生成器代码的 consumer 校验导出的 OBJ、面字段和参数数据，比较开启/关闭捕获时的几何与标签，并覆盖结构分支的确定性种子。只有 [参数化契约](parametric-description-contract.md)的就绪条件均满足时，才更新就绪清单。完成标准：描述在独立进程中可用，目标面归属、位置、外法向和捕获不变性有多 seed 证据。

### 3. 模型机器门禁和人工审查

运行当前模型、字段及参数化门禁，保存每接口的机器证据；当前接口状态脚本要求至少 20 个几何 episode 和 20 个捕获不变性 seed。将与机器证据绑定的接口记录转为 `awaiting_review` 并提交。Web 中至少查看覆盖已知结构分支的十个 seed，旋转检查几何、逐面字段、目标面政策及参数化叠层。发现问题先保存并提交 `needs_fix` 与具体 seed/字段，再修源数据、重跑门禁并复审；人工接受并提交后，生成接口才为 `ready`。参见 [Web 审查说明](generator-ui.md)和 [接口状态 ADR](../adr/0009-git-owned-interface-review-state.md)。

### 4. 设计并导出接口专属轨迹

先对照 Spraybot 原生 Chair、OpusChair、CarBumper 的规划先例，声明本接口实际要喷的表面、喷幅与喷距等工艺假设、构件分区和允许连接的笔画。轨迹程序位于 `scripts/spraybot_trajectory/`，消费同一 interface ID/seed 的已导出模型、面字段、参数化描述及必要先验。按构件整体规划连续笔画，处理遮挡、接头、板边、杆件和转角；导出 PaintDS 与 Web 配对数据，回读坐标和喷向，并绑定模型与源码哈希。完整规则见 [轨迹生成说明](trajectory-generation.md)。完成标准：可为审查 seed 重现与模型配对的笔画，并能追溯每笔来源。

### 5. 轨迹机器门禁和人工审查

在**实际导出并交给 Web 的轨迹**上检查模型配对、喷枪中心点和移动线段侵入、按路径采样的射线首个命中及喷向、可判定的急转和接口特定净空。先保留失败候选，再针对整条笔画或构件路径修复；每次修改重新生成相关结构分支的配对证据。覆盖率、目标面距离、笔画数和绕行程度用于定位问题，不能用统一数值取代质量判断。原生轨迹可作先例和校准样本；现有几何规则不等于通用工艺标准。

Web 中逐 seed、逐笔检查遗漏面、喷向、平滑与连贯、部件间碰撞和喷涂范围。机器 passed 仍需人工结论。问题按 seed/笔画记录并先提交审查意见，修复同类结构后复审；最终 `accepted` 记录绑定模型和轨迹哈希，并在 Git 提交后正式生效。轨迹或影响产物的生成代码变化使旧结论失效，必须重建相关证据。实体喷枪、机器人可达与涂层质量保留为独立的后续验证。

轨迹审查结论为 `pending`、`accepted`、`needs_fix` 或 `deferred`。`deferred`（搁置）表示人工主动决定暂停该接口的轨迹修复与复审：它与 `needs_fix` 不同，不携带待修复的具体缺陷清单，仅表示停止投入；已注册接口、模型、参数化描述与既有审查历史全部保留。搁置接口恢复时按 `needs_fix` 同样的规则处理：先重建机器证据与配对轨迹，再进入人工复审，旧结论不自动恢复。

### 6. 交接与版本一致性

在本机提交代码、审查记录和经验记录，推送后让生成主机拉取同一源码提交，再生成或重新部署。记录主机实际 Git HEAD、运行的生成/规划源码哈希、review root、trajectory root，以及模型/轨迹文件哈希。不要用主机上的独立提交承载同一轮代码变更；若确有主机环境专属操作，另记其与源码版本的关系。交接给 Spraybot 的是已版本化、同坐标与单位约定的导出数据和轨迹，不是 Web 页面上的截图状态。

生成不是跨平台位级可复现的：同一接口与 seed 在不同主机（不同 bpy 构建或平台）导出的模型字节不同，模型哈希随之不同，边界样本的机器门禁结论也可能翻转。因此模型/轨迹哈希证据只对产出主机有意义；需要复现或复审时回到产出主机或其留存副本，不要在另一台机器上重新生成来"验证"原证据。证据与工作区应放在实例回收不影响的持久存储上（当前 spraybot 主机为 `/sfs/hqb/`），用户空间目录会随实例切换被回收。

## 门禁如何进化

人工审查发现缺陷时，先判定它是否能对导出工件与轨迹稳定地程序化识别。能识别的，保存失败样本，写会失败的回归检查，再实现门禁；记录检查的适用结构、输入、容差与误报边界，并在多个 seed 和相关原生先例上校准。不能可靠识别的，写入人工审查清单和接口经验记录。硬门禁只声明其实际检测的几何或数据性质；涂层质量与机器人运动需要相应工艺证据。新增规则同时更新对应检查代码、测试、本流程或具体契约，避免只有文档或只有代码。

## 经验回流

每个有实质审查或修复的接口维护 `docs/spraybot/interfaces/<group>__<name>.md`。每一轮记录：日期与提交、症状及 seed/笔画、结构适用范围、根因、修复策略、重验数据、仍未验证的事项。正式状态、审查人、原话和哈希留在 `reviews/` JSON，经验记录链接这些证据，不替代它们。修复前先提交审查问题，修复后补充结果；跨接口可复用的规则再提炼回本流程、相应契约或项目 Skill。每轮收尾检查两处是否同步，防止同一失误在下个接口重演。

Armchair 的实际过程见 [接口经验记录](interfaces/workpiece__armchair.md)。它是案例，不是所有工件的笔画模板。面字段细节见 [兼容契约](compatibility-contract.md)，参数曲面细节见 [参数化契约](parametric-description-contract.md)，Web 操作见 [生成器说明](generator-ui.md)，轨迹细节见 [轨迹生成说明](trajectory-generation.md)。
